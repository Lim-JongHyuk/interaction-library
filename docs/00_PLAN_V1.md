**목차**

**1. 프로젝트 개요**

▍ **1.1 배경**

최근 웹은 정적인 레이아웃을 넘어 **모션(motion)과 마이크로 인터랙션**이
브랜드 경험과 전환율을 좌우하는 시대로 이동했다. 그러나 개발자·디자이너
입장에서 ‘좋은 움직임’을 매번 처음부터 구현하는 것은 비용이 크고, 재현
가능한 형태로 팀 안에 축적되지 않는다.

Animata, React Bits, OriginKit 같은 라이브러리가 성장한 이유가 여기에
있다. 이들은 “눈으로 보고 → 코드를 복사하거나 CLI로 설치 → 프로젝트에
붙여 커스터마이즈”라는 단순한 흐름으로 **모션 구현의 진입장벽을
제거**했다. 본 프로젝트는 이 검증된 패턴을 계승하되, ‘모션을 명시적으로
정의(spec)하고 문서화’하는 축을 강화한 라이브러리를 지향한다.

▍ **1.2 한 줄 정의**

**MotionKit 이란?** 라이브 프리뷰 · 실시간 파라미터 조정 · 다중 설치
경로(copy / CLI / MCP)를 갖춘, 모션이 스펙 단위로 정의된 오픈 컴포넌트
갤러리.

▍ **1.3 목적 및 목표**

**정성 목표**

- 모션 구현을 **“찾기→미리보기→가져오기” 3단계**로 압축해 개발 생산성을
  높인다.

- 각 모션을 트리거·타이밍·이징·의존성까지 정의된 ‘명세’로 제공해 팀 내
  재사용성과 일관성을 확보한다.

- 오픈소스 기여 구조로 카탈로그를 지속 확장 가능한 생태계로 만든다.

▍ **2.2 계승할 강점 (Keep)**

- **즉시성** — 컴포넌트마다 인터랙티브 라이브 프리뷰가 페이지 최상단에
  위치.

- **다중 설치 경로** — copy-paste와 CLI 레지스트리를 동시 제공(진입장벽
  최소화).

- **코드 소유권** — 패키지 의존이 아니라 소스가 사용자 코드베이스로
  복사되는 구조.

- **카테고리 IA** — 사이드바 기반 탐색 + 검색으로 대규모 카탈로그를
  견딤.

▍ **2.3 우리의 차별화 (Differentiate)**

- **모션 스펙 정의** — 각 모션을 트리거/타이밍/이징/의존성/접근성이
  명시된 ‘정의서’로 표준화(§5 참조). 단순 코드 나열을 넘어선다.

- **실시간 파라미터 스튜디오** — duration·delay·easing·stagger를
  슬라이더로 조정하면 프리뷰와 코드가 동시에 갱신.

- **3-way 설치 + MCP** — copy / CLI 레지스트리 / MCP 커넥터를 모두
  지원해 AI 에이전트 워크플로우까지 포섭.

- **접근성 기본 내장** — 모든 모션이 prefers-reduced-motion 대응을 기본
  코드에 포함.

**5. 모션 정의 스키마 (Motion Spec)**

본 프로젝트의 핵심 자산은 코드가 아니라 **‘정의된 모션’**이다. 모든
컴포넌트는 아래 스키마를 갖춘 하나의 스펙 문서로 관리되며, 이 스펙에서
프리뷰·코드·설치·문서가 파생된다.

▍ **5.1 스펙 필드 정의**

| **필드**         | **타입**   | **설명**                                                   |
|------------------|------------|------------------------------------------------------------|
| **id / slug**    | string     | 고유 식별자. URL·레지스트리 경로에 사용 (예: text/shuffle) |
| **name**         | string     | 표시 이름 (예: Shuffle Text)                               |
| **category**     | enum       | §4.2 카테고리 중 하나                                      |
| **tags**         | string\[\] | 검색·필터용 키워드 (text, glitch, hero …)                  |
| **trigger**      | enum       | mount · in-view · hover · click · scroll · drag · loop     |
| **params**       | object\[\] | 조정 가능한 파라미터 정의 (아래 5.2)                       |
| **dependencies** | string\[\] | 필요 라이브러리 (motion / gsap / none)                     |
| **variants**     | enum\[\]   | 제공 코드 변형 (react-ts-tw · react-js-css …)              |
| **a11y**         | object     | reduced-motion 대체 동작 · 포커스/ARIA 유의사항            |
| **install**      | object     | copy · cliRegistryUrl · mcpRef                             |
| **credits**      | object     | 제작자 · 원출처 · 라이선스                                 |

▍ **5.2 파라미터(param) 정의 규격**

스튜디오(실시간 조정 패널)와 코드 생성이 이 정의를 공통 소스로 사용한다.

| **속성**         | **예시**       | **설명**                                  |
|------------------|----------------|-------------------------------------------|
| key              | duration       | props 이름 / 코드 변수명                  |
| control          | slider         | slider · number · select · color · toggle |
| min / max / step | 0.1 / 2 / 0.05 | 슬라이더 범위(수치형)                     |
| default          | 0.6            | 기본값(코드 초기값과 일치)                |
| unit             | s              | 표시 단위(s, px, deg …)                   |

▍ **5.3 예시 — Shuffle Text 정의(요약)**

| **필드**     | **값**                                                                    |
|--------------|---------------------------------------------------------------------------|
| slug         | text/shuffle                                                              |
| trigger      | in-view (뷰포트 진입 시 1회) + hover 재생 옵션                            |
| params       | duration(0.1~2s) · stagger(0~0.2s) · shuffleTimes(1~10) · charset(select) |
| dependencies | motion                                                                    |
| variants     | react-ts-tw · react-ts-css · react-js-tw · react-js-css                   |
| a11y         | reduced-motion 시 셔플 생략하고 최종 텍스트 즉시 표시                     |
| install      | copy / CLI 레지스트리 / MCP ref 모두 제공                                 |

**왜 스키마 우선인가** 정의를 단일 소스(single source of truth)로 두면
프리뷰·문서·코드·레지스트리·MCP 응답이 자동 일관성을 갖고, 컴포넌트 추가
시 반복 작업이 최소화된다.

**6. 기능 명세**

▍ **6.1 우선순위 (MoSCoW)**

| **기능**                 | **설명**                                               | **우선순위**    |
|--------------------------|--------------------------------------------------------|-----------------|
| 라이브 프리뷰            | 컴포넌트 상세 상단에서 실제 동작을 인터랙티브하게 렌더 | **Must**        |
| 코드 뷰 + 복사           | 변형별 코드 표시, 원클릭 복사, 구문 강조               | **Must**        |
| 설치 안내(copy/CLI)      | shadcn 스타일 레지스트리 URL + 수동 설치 스텝          | **Must**        |
| 카테고리 탐색 + 검색     | 사이드바 IA, 태그 필터, 즉시 검색                      | **Must**        |
| 다크/라이트 · 반응형     | 테마 토글, 모바일 대응                                 | **Must**        |
| 실시간 파라미터 스튜디오 | 슬라이더/셀렉트로 props 조정 → 프리뷰·코드 동시 갱신   | **Should**      |
| 다중 코드 변형           | TS/JS × Tailwind/CSS 탭 전환                           | **Should**      |
| MCP 커넥터               | 카탈로그를 MCP 서버로 노출해 AI 에이전트 연동          | **Could**       |
| 쇼케이스/템플릿          | 컴포넌트 조합 데모 페이지                              | **Could**       |
| 즐겨찾기/컬렉션          | 로컬 저장 기반 북마크                                  | **Won’t(초기)** |

▍ **6.2 컴포넌트 상세 페이지 구성**

5.  **헤더** — 이름 · 설명 · 태그 · 트리거 배지 · 의존성.

6.  **라이브 프리뷰** — 재생/일시정지·리플레이 컨트롤, 배경 토글.

7.  **파라미터 스튜디오** — §5.2 정의 기반 컨트롤. 변경 시 프리뷰+코드
    동기화.

8.  **코드** — 변형 탭(TS/JS·Tailwind/CSS), 복사 버튼, 의존성 안내.

9.  **설치** — CLI(레지스트리 URL) / 수동 스텝 / MCP ref 탭.

10. **모션 정의서** — 트리거·타이밍·이징·접근성·크레딧 표.

11. **관련 컴포넌트** — 같은 카테고리/태그 추천.

| 레지스트리      | shadcn registry 규격(JSON)        | CLI 설치 호환, 생태계 표준                           |
| MCP             | MCP 서버(카탈로그 노출)           | AI 에이전트 연동(확장 단계)                          |
| 배포            | Vercel                            | Next 네이티브, 프리뷰 배포·엣지 캐싱                 |

▍ **7.2 데이터 흐름 (스펙 우선 파이프라인)**

12. 스펙 소스: 각 컴포넌트의 정의(메타데이터) + 소스코드(변형별)를
    저장소에 둔다.

13. 빌드 시: 스펙을 파싱해 (a) 문서 페이지, (b) 레지스트리 JSON, (c) MCP
    카탈로그, (d) 검색 인덱스를 생성.

14. 런타임: 상세 페이지가 프리뷰를 렌더하고, 스튜디오 컨트롤이 params
    정의를 읽어 코드 문자열을 생성.

15. 설치: 사용자는 CLI가 레지스트리 JSON을 받아 파일 생성 / 또는 복사 /
    또는 MCP로 에이전트가 취득.

▍ **7.3 Vercel 배포 구성**

- **빌드** — 정적 우선(SSG). 상세 페이지는 빌드타임 프리렌더, 프리뷰만
  클라이언트 하이드레이션.

- **프리뷰 배포** — PR 단위 미리보기로 신규 컴포넌트 검수.

- **도메인/캐싱** — 커스텀 도메인 연결, 정적 자산 엣지 캐싱, OG 이미지
  자동 생성.

- **성능 예산** — 프리뷰 컴포넌트는 지연 로드(in-view mount)로 초기 번들
  최소화.

**성능 주의** 여러 모션이 동시에 렌더되는 카탈로그 그리드는 성능 병목이
되기 쉽다. 뷰포트 진입 시에만 애니메이션을 활성화하고, 목록에서는 경량
썸네일/포스터를 우선 사용한다.

**8. 디자인 방향**

▍ **8.1 톤 & 무드**

개발자 친화적이면서 ‘움직임 자체가 주인공’이 되도록 UI는 절제한다.
콘텐츠(프리뷰)가 빛나도록 크롬(chrome)은 뉴트럴·저채도로 유지하고,
포인트 컬러 한 축으로 상호작용을 표시한다.

| **요소**      | **방향**                                                        |
|---------------|-----------------------------------------------------------------|
| 레이아웃      | 좌측 고정 사이드바 + 본문 2단(문서/프리뷰). 넓은 프리뷰 캔버스. |
| 타이포        | 가변 산세리프(본문) + 모노스페이스(코드). 명확한 위계.          |
| 컬러          | 뉴트럴 그레이스케일 베이스 + 인디고/틸 액센트 1~2색. 다크 우선. |
| 프리뷰 캔버스 | 격자/도트 배경 토글, 라이트·다크 대비 확인 가능.                |
| 모션(자체 UI) | 과하지 않게 — 호버·포커스·페이지 전환에 절제된 이징 적용.       |

  함.
